Laboratorium 1: HTML5, CSS i Flask

HTML5, CSS, API Flask, Docker i GitHub

Plan pracy: 180 minut

Materiał jest instrukcją do wykorzystania podczas zajęć i późniejszej pracy, nie tekstem do przeczytania w całości na sali. W 3 godziny wykonujemy ścieżkę podstawową, kopiując kompletne przykłady i samodzielnie zmieniając wskazane fragmenty. Przepisywanie całego kodu oraz wykonanie wszystkich eksperymentów wymaga dodatkowego czasu.

Budżet oznacza 180 minut pracy (4 × 45 minut), z przerwą organizowaną osobno. Jeśli zajęcia trwają 3 × 45 minut, pełny zakres nie zmieści się w jednym spotkaniu.

45–65 min Sekcja 3: CSS Wspólny arkusz i sprawdzenie układu

Prowadzący powinien sprawdzić z wyprzedzeniem docker pull python:3.12-slim i pierwszą budowę obrazu kalkulatora; instalacji narzędzi, zakładania kont i długiego pobierania nie wliczamy do powyższego planu. Jeśli test trwa ponad 10 minut, odpowiednio skróć zakres pracy lub dokończ wskazane ćwiczenia po zajęciach.

Ścieżka podstawowa bez lokalnego Pythona

  1. W sekcjach 1–3 skopiuj przykłady, zmień autora i dwa akapity, sprawdź menu oraz wspólny CSS.
  2. W sekcji 4 pomiń krok 1 z lokalną instalacją; wykonaj kroki 2–7 i pozostaw static/app.js pusty.
  3. Wykonaj kroki 1–7 sekcji 6, zbuduj obraz i uruchom kontener. Pozostaw go działającego. Wróć do prób API w sekcji 4.8, pomijając lokalne polecenie python.
  4. Dopiero teraz wykonaj sekcję 5: dodaj fetch(), przebuduj obraz i sprawdź wynik na stronie.
  5. W sekcji 7 przenieś uruchomienie do Compose, a w sekcji 8 zapisz i wyślij projekt.

Na zajęciach obowiązkowe: trzy strony statyczne, wspólny CSS, poprawne GET dla 2 i 3, jedna próba błędnych danych, formularz z fetch, uruchomienie Docker/Compose i push na GitHub. Dodatkowe eksperymenty HTML/CSS, rozbudowana personalizacja, wszystkie przypadki graniczne API oraz ponowne klonowanie repozytorium są do wykonania po zajęciach lub w pozostałym czasie. Wyjaśnienia pozostają na stronie jako materiał do powtórki.

Sekcja 1. Pierwsza strona HTML5

Cel tej sekcji

Przygotujesz stronę główną osobistej witryny. Wpiszesz własną treść, otworzysz dokument w przeglądarce i sprawdzisz, jak znaczniki HTML opisują strukturę strony. Możesz przedstawić siebie, fikcyjną postać albo wybrany temat. Nie musisz podawać prawdziwych danych osobowych.

To pierwszy etap laboratorium: HTML5 → CSS → Flask → Dockerfile → Docker Compose → GitHub. W tej sekcji pracujemy wyłącznie z HTML. Podstrony uzupełnimy w następnym etapie.

1. Przygotuj katalog projektu

Utwórz katalog personal-website. W Visual Studio Code wybierz File → Open Folder i otwórz ten katalog. Następnie utwórz cztery puste pliki:

personal-website/
├── index.html
├── about.html
├── interests.html
└── style.css
Plik Przeznaczenie
index.html Strona główna z powitaniem
about.html Podstrona „O mnie”
interests.html Podstrona „Zainteresowania”
style.css Wspólny arkusz stylów, używany w kolejnej sekcji

Nazwa index.html jest zwyczajową nazwą strony domyślnej w katalogu witryny. Sprawdź rozszerzenia plików: index.html.txt nie jest plikiem index.html.

2. Wpisz kompletny dokument HTML5

Otwórz index.html i wprowadź poniższy kod. Przycisk kopiowania w prawym górnym rogu bloku pozwala skopiować cały przykład.

<!DOCTYPE html>
<html lang="pl">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Jan Kowalski — strona osobista</title>
</head>
<body>
    <header>
        <h1>Jan Kowalski</h1>
        <p>Witaj na mojej stronie internetowej!</p>
    </header>

    <nav aria-label="Nawigacja główna">
        <ul>
            <li><a href="index.html">Strona główna</a></li>
            <li><a href="about.html">O mnie</a></li>
            <li><a href="interests.html">Zainteresowania</a></li>
        </ul>
    </nav>

    <main>
        <section>
            <h2>Moja pierwsza strona</h2>
            <p>
                Uczę się projektowania aplikacji internetowych.
                Na tej stronie przedstawiam siebie i swoje zainteresowania.
            </p>
            <p>
                W kolejnych etapach dodam style CSS,
                a następnie uruchomię stronę jako aplikację Flask.
            </p>
        </section>
    </main>

    <footer>
        <p>Autor: Jan Kowalski</p>
    </footer>
</body>
</html>

Zapisz plik: Ctrl+S w Windows/Linux lub Cmd+S w macOS.

3. Zrozum szkielet dokumentu

Znaczniki i elementy

HTML opisuje strukturę i znaczenie treści. Zwykle element składa się ze znacznika otwierającego, treści i znacznika zamykającego:

<p>Witaj na mojej stronie!</p>

<p> rozpoczyna akapit, a </p> go zamyka. Ukośnik oznacza znacznik zamykający. Nie wszystkie elementy mają znacznik zamykający: przykładowo meta go nie ma.

Elementy mogą zawierać inne elementy. Wcięcia pokazują to zagnieżdżenie i ułatwiają czytanie kodu. Zamykaj elementy w odwrotnej kolejności do ich otwierania.

Typ dokumentu i język

<!DOCTYPE html>
<html lang="pl">

Deklaracja <!DOCTYPE html> uruchamia standardowy tryb interpretacji HTML w przeglądarce. Element html obejmuje dokument. Atrybut lang="pl" określa język treści, co pomaga między innymi czytnikom ekranu.

Atrybut to dodatkowa informacja zapisana w znaczniku otwierającym. W tym przykładzie nazwą atrybutu jest lang, a jego wartością pl.

Metadane w head

Fragment Znaczenie
<meta charset="UTF-8"> Deklaruje kodowanie znaków. Sam plik również zapisz jako UTF-8.
<meta name="viewport" content="width=device-width, initial-scale=1.0"> Ustawia obszar wyświetlania zgodnie z szerokością urządzenia.
<title>Jan Kowalski — strona osobista</title> Określa tytuł dokumentu widoczny na karcie przeglądarki.

head zawiera metadane. Widoczną treść umieszczamy w body. Ustawienie viewport przyda się przy tworzeniu układu na telefon; samo nie zapewnia jeszcze responsywności.

Semantyczny podział body

Element Rola w naszej stronie
header Imię i nazwisko oraz powitanie
nav Główna nawigacja
main Główna treść dokumentu
section Tematycznie spójny fragment z własnym nagłówkiem
footer Informacja o autorze

W naszym dokumencie używamy jednego widocznego elementu main. Elementy semantyczne opisują przeznaczenie treści. Wygląd nadamy im później przez CSS.

Nagłówki i akapity

h1 to główny nagłówek strony. h2 oznacza nagłówek sekcji, a p akapit. Dobieraj poziom nagłówka według hierarchii treści, a nie rozmiaru liter.

AdnotacjaTytuł karty a nagłówek strony

Zmień sam title, zapisz plik i odśwież przeglądarkę. Zmieni się podpis karty. Zmiana h1 zmieni nagłówek w treści dokumentu. To dwa różne elementy.

4. Przeanalizuj nawigację

<a href="about.html">O mnie</a>

Element a tworzy odnośnik. Atrybut href podaje jego cel, a tekst między znacznikami jest etykietą widoczną na stronie.

Adres about.html jest ścieżką względną. Przeglądarka szuka pliku w tym samym katalogu co bieżący dokument. Dlatego wszystkie trzy pliki HTML umieszczamy obok siebie.

Menu zapisaliśmy jako listę: ul to lista nieuporządkowana, a każdy li jest jej pozycją. Atrybut aria-label nadaje obszarowi nawigacji nazwę dla technologii wspomagających.

WażnePodstrony są jeszcze puste

Kliknięcie „O mnie” lub „Zainteresowania” otworzy pusty dokument, jeżeli utworzyłeś odpowiedni pusty plik. To oczekiwany stan tego etapu. Wróć przyciskiem Wstecz; zawartość podstron dodamy w kolejnej sekcji.

5. Otwórz stronę w przeglądarce

  1. Znajdź index.html w menedżerze plików.
  2. Otwórz go w przeglądarce lub przeciągnij do jej okna.
  3. Sprawdź tytuł karty, nagłówek, menu, akapity i stopkę.

Adres rozpoczynający się od file:/// oznacza odczyt lokalnego pliku. Nie działa tu jeszcze serwer HTTP ani aplikacja Flask.

Strona będzie miała domyślny wygląd przeglądarki. Menu może być pionową listą z punktami. Plik style.css jest pusty i nie został jeszcze podłączony.

6. Uzupełnij własną treść

Zastąp przykładowe dane własnymi lub wymyślonymi. Zmień:

  • tytuł dokumentu w title;
  • imię i nazwisko w h1 oraz stopce;
  • powitanie w nagłówku;
  • nagłówek sekcji i dwa akapity opisu.

Zachowaj strukturę dokumentu. Samodzielnie zdecyduj, jaki temat rozwiniesz na podstronie „Zainteresowania”. Napisz kilka zdań, które go zapowiadają.

Po każdej zmianie zapisz plik i odśwież przeglądarkę: Ctrl+R lub Cmd+R. Samo wpisanie tekstu w edytorze nie zmienia pliku na dysku.

7. Opcjonalnie: wykonaj dwa eksperymenty

Nowa linia w kodzie a nowy akapit

Zastąp jeden akapit poniższym fragmentem:

<p>
    Pierwsze zdanie.
    Drugie zdanie.
    Trzecie zdanie.
</p>

Zapisz plik i sprawdź efekt. Przy domyślnym sposobie wyświetlania przeglądarka traktuje przejścia do nowego wiersza i serie spacji jak pojedynczy odstęp. Tekst zawija się zależnie od dostępnej szerokości.

Następnie porównaj z trzema osobnymi akapitami:

<p>Pierwszy akapit.</p>
<p>Drugi akapit.</p>
<p>Trzeci akapit.</p>

Znaczenie wyróżnienia

Wstaw do jednego akapitu element strong:

<p>
    Na tych zajęciach tworzę
    <strong>własną stronę internetową</strong>.
</p>

strong oznacza treść o dużej wadze i domyślnie jest wyświetlany pogrubieniem. Zwróć uwagę: zamykamy strong przed zamknięciem otaczającego go p.

8. Sprawdź rezultat

To lista kontrolna wykonania zadania, nie punktowany test.

Jeżeli widzisz sam kod zamiast strony, sprawdź rozszerzenie pliku i upewnij się, że otwierasz go w przeglądarce. Jeżeli widzisz poprzednią treść, zapisz plik i sprawdź, czy edytujesz ten sam dokument, który jest otwarty w przeglądarce.

Rezultat: masz stronę główną z własną treścią. Następny etap to uzupełnienie dwóch podstron i sprawdzenie nawigacji między nimi.

Sekcja 2. Dwie podstrony i nawigacja

W pierwszym etapie powstała strona główna. Teraz uzupełnisz about.html i interests.html, a następnie sprawdzisz przechodzenie między trzema dokumentami. Nadal nie używamy CSS ani Flaska.

Docelowo wszystkie trzy pliki mają znajdować się w jednym katalogu:

personal-website/

Otwórz pusty plik about.html i wpisz cały poniższy dokument. Nie wklejaj go do index.html: każda podstrona jest osobnym plikiem z własnym head i body.

2. Przeanalizuj różnice względem strony głównej

Szkielet dokumentu pozostaje taki sam. Zmieniliśmy tytuł karty, treść main i oznaczenie bieżącej pozycji menu.

Fragment Dlaczego go zmieniamy?
title Pozwala rozpoznać podstronę na karcie przeglądarki.
h2 w main Wskazuje temat bieżącej podstrony.
Akapity i lista Zawierają treść właściwą dla strony „O mnie”.

4. Ujednolicenie menu na stronie głównej

W index.html znajdź cały element nav i zastąp go poniższym fragmentem:

<nav aria-label="Nawigacja główna">
    <ul>
        <li><a href="index.html" aria-current="page">Strona główna</a></li>
        <li><a href="about.html">O mnie</a></li>
        <li><a href="interests.html">Zainteresowania</a></li>
    </ul>

W każdym pliku menu zawiera te same etykiety, adresy i kolejność odnośników. Różni się położeniem aria-current="page":

Dokument Odnośnik oznaczony jako bieżący
index.html Strona główna
about.html O mnie
interests.html Zainteresowania

W każdym z tych menu oznacz dokładnie jedną pozycję jako bieżącą. Nie przenoś menu z about.html do pozostałych plików bez poprawienia tego oznaczenia.

5. Rozróżnij rodzaje adresów

Porównaj trzy zapisy:

<a href="about.html">O mnie</a>
<a href="https://developer.mozilla.org/pl/docs/Web/HTML">Dokumentacja HTML</a>
<a href="#top">Początek strony</a>
Adres Działanie
about.html Otwiera dokument względem katalogu bieżącej strony.
https://developer.mozilla.org/pl/docs/Web/HTML Otwiera wskazany adres w internecie.
#top Przechodzi do elementu o id="top" w bieżącym dokumencie.

Opcjonalnie, aby wypróbować trzeci wariant, dodaj id="top" do istniejącego nagłówka strony:

<header id="top">
    <h1>Jan Kowalski</h1>
    <p>Moja osobista witryna internetowa</p>
</header>

Następnie dodaj odnośnik „Początek strony” do stopki. Na krótkim dokumencie przewinięcie może być niezauważalne, ale w adresie pojawi się fragment #top. Wartość id musi być unikalna w obrębie dokumentu.

WażneDlaczego bez ukośnika na początku?

W tym ćwiczeniu zapisuj href="about.html", a nie href="/about.html". Początkowy ukośnik oznacza ścieżkę od korzenia bieżącego adresu. Przy otwieraniu lokalnych plików nie wskazuje katalogu projektu; na serwerze wskazuje korzeń witryny. Może więc prowadzić do innego miejsca niż oczekujesz.

Nie wpisuj też ścieżek do własnego dysku, takich jak C:\Users\Jan\.... Menu ma działać również po przeniesieniu całego katalogu na inny komputer.

Odnośniki z przykładów otwierają dokumenty w tej samej karcie. Przycisk Wstecz w przeglądarce pozwala wrócić do poprzednio odwiedzonej strony.

5. Przeanalizuj typografię i dziedziczenie

W regule body ustawiliśmy wspólne właściwości tekstu:

body {
    font-family: Arial, Helvetica, sans-serif;
    font-size: 1rem;
    line-height: 1.6;
}

Przeglądarka próbuje użyć Arial, potem Helvetica, a następnie dostępnej czcionki bezszeryfowej. Lista pozwala wyświetlić tekst również na komputerze bez pierwszej z podanych czcionek.

Jednostka rem odnosi się do rozmiaru czcionki elementu głównego html. Przy typowych ustawieniach 1rem odpowiada 16 pikselom, ale użytkownik może zmienić te ustawienia. line-height: 1.6 określa wysokość wiersza jako 1,6 rozmiaru czcionki danego elementu.

Wiele właściwości tekstu, w tym krój pisma i kolor, jest dziedziczonych przez elementy potomne. Nie musimy więc osobno przypisywać czcionki każdemu akapitowi. Reguły dla nagłówków i odnośników mogą nadpisywać wybrane wartości.

6. Zrozum odstępy i szerokość

Każdy element jest opisywany przez model pudełkowy: treść, wewnętrzny odstęp padding, obramowanie border i zewnętrzny odstęp margin.

Właściwość Zastosowanie w przykładzie

border: 1px solid #cbd5e1 Tworzy cienką, ciągłą ramkę sekcji.
margin-bottom: 1rem Dodaje odstęp pod sekcją.

Na początku arkusza ustawiliśmy box-sizing: border-box dla wszystkich elementów za pomocą selektora *. Dzięki temu zadeklarowana szerokość obejmuje również padding i obramowanie. Ułatwia to utrzymanie elementów w granicach ekranu.

8. Zobacz, jak Flexbox układa menu

nav ul {
    display: flex;
    flex-wrap: wrap;
    gap: 0.5rem;
    margin: 0;
    padding: 0;
    list-style: none;
}

display: flex zmienia układ dzieci listy, czyli elementów li. Domyślnie są rozmieszczane w wierszu. gap określa odstępy między nimi, a flex-wrap: wrap pozwala przejść do kolejnego wiersza, gdy brakuje miejsca.

W regule nav a używamy display: block, aby obszar odnośnika wraz z wewnętrznymi odstępami tworzył wyraźne pole do kliknięcia.

Zwęż okno przeglądarki. Menu powinno zawijać się zamiast wymagać sztywnej szerokości strony. Ten prosty układ nie wymaga jeszcze reguł @media.

3. Napisz kompletny backend

W app.py wpisz:

from math import isfinite

from flask import Flask, jsonify, render_template, request

app = Flask(__name__)


@app.get("/")
def home() -> str:
    """Render the calculator page."""
    return render_template("index.html")


@app.get("/api/add")
def add():
    """Return the sum of two finite query parameters as JSON."""
    try:
        a = float(request.args["a"])
        b = float(request.args["b"])
    except (KeyError, ValueError):
        return jsonify(error="Provide two numbers: a and b."), 400

    if not isfinite(a) or not isfinite(b):
        return jsonify(error="Numbers must be finite."), 400

    result = a + b
    if not isfinite(result):
        return jsonify(error="The result is outside the supported range."), 400

    return jsonify(a=a, b=b, operation="add", result=result)

home() zwraca HTML, a add() odpowiedź JSON. Obie funkcje działają w tym samym procesie aplikacji, ale obsługują różne adresy.

@app.get(...) rejestruje trasę dla metody GET. Nie dodajemy danych do bazy ani nie zmieniamy stanu serwera: wykonujemy obliczenie na podstawie parametrów żądania.

4. Zrozum parametry GET

Dla adresu:

/api/add?a=2&b=3
  • /api/add jest ścieżką endpointu;
  • ? rozpoczyna parametry zapytania;
  • a=2 przypisuje parametr a;
  • & oddziela parametry;
  • b=3 przypisuje parametr b.

Flask udostępnia je w request.args. Wartości są tekstem: request.args["a"] odczytuje "2", a float(...) zamienia tę wartość na liczbę. Bez konwersji dodawanie dwóch tekstów połączyłoby je: "2" + "3" daje "23".

Parametry zapytania są widoczne w adresie i mogą trafić do historii przeglądarki oraz logów serwera. W tym ćwiczeniu przesyłamy zwykłe liczby; nie jest to miejsce na hasła.

5. Przeanalizuj walidację i JSON

try obejmuje odczyt i konwersję parametrów. Brak a lub b powoduje błąd odczytu, a tekst taki jak hello błąd konwersji. Przechwytujemy te przypadki i zwracamy komunikat ze statusem 400 Bad Request.

isfinite() odrzuca wartości takie jak NaN i nieskończoność. Sprawdzamy też wynik: suma dwóch bardzo dużych, skończonych liczb może przekroczyć zakres float.

Poprawne żądanie daje status 200 i obiekt JSON:

{
  "a": 2.0,
  "b": 3.0,
  "operation": "add",
  "result": 5.0
}

jsonify() tworzy odpowiedź z typem treści application/json. Nazwy pól są częścią naszego kontraktu API: frontend będzie odczytywał result przy sukcesie i error przy błędzie. Kolejność pól w obiekcie JSON nie ma znaczenia.

Korzystamy z liczb zmiennoprzecinkowych. Przykład 0.1 + 0.2 może dać 0.30000000000000004. To własność reprezentacji binarnej float, a nie błąd przesyłania JSON.

Sekcja 5. Fetch: wynik JSON na stronie HTML

API już działa niezależnie od interfejsu. Teraz dodasz JavaScript, który pobierze odpowiedź i pokaże wynik bez przechodzenia do nowego dokumentu.

1. Wpisz kompletny app.js

W static/app.js umieść:

const form = document.querySelector("#calculator-form");
const result = document.querySelector("#result");
const button = form.querySelector("button");

form.addEventListener("submit", async (event) => {
    event.preventDefault();

    const formData = new FormData(form);
    const params = new URLSearchParams();
    params.set("a", formData.get("a"));
    params.set("b", formData.get("b"));

    button.disabled = true;
    result.textContent = "Obliczam…";

    try {
        const response = await fetch(`/api/add?${params.toString()}`);
        const data = await response.json();

        if (!response.ok) {
            result.textContent = `Błąd API: ${data.error}`;
            return;
        }

        result.textContent = `${data.a} + ${data.b} = ${data.result}`;
    } catch (error) {
        result.textContent = "Nie udało się pobrać odpowiedzi. Sprawdź serwer i połączenie.";
        console.error(error);
    } finally {
        button.disabled = false;
    }
});

Zapisz plik. W wariancie Docker przebuduj obraz i uruchom nowy kontener, ponieważ poprzedni zawierał pusty skrypt:

docker stop flask-calculator-lab
docker build -t flask-calculator:lab .
docker run --rm --name flask-calculator-lab -p 127.0.0.1:5000:5000 flask-calculator:lab

Polecenia wykonaj w drugim terminalu, w katalogu flask-calculator. W wariancie z lokalnym Pythonem nie przebudowujesz obrazu. Odśwież stronę główną i wyślij formularz. Adres karty powinien pozostać /, a wynik pojawić się pod formularzem.

2. Znajdź elementy i przechwyć formularz

document.querySelector() wyszukuje element w dokumencie. Używamy tych samych identyfikatorów co w HTML: calculator-form i result. form.querySelector() ogranicza wyszukiwanie przycisku do formularza.

Skrypt w HTML ma atrybut defer: zostanie wykonany po przetworzeniu dokumentu, kiedy elementy formularza już istnieją.

Zdarzenie submit występuje po wysłaniu formularza, również klawiszem Enter. event.preventDefault() zatrzymuje domyślną nawigację do odpowiedzi JSON. Zamiast niej wykonamy żądanie przez fetch().

3. Zbuduj parametry zapytania

new FormData(form) odczytuje wartości pól według ich atrybutów name. URLSearchParams buduje i koduje część adresu po ?. Nie sklejamy ręcznie wartości użytkownika z & i =.

Dla a=2 i b=3 powstaje adres:

/api/add?a=2&b=3

W JavaScripcie zapis między znakami backtick, z ${...}, jest literałem szablonowym. Wstawia wartość do tekstu w przeglądarce. To mechanizm JavaScriptu, niezależny od serwerowych szablonów Jinja.

4. Wyślij żądanie i odczytaj odpowiedź

fetch() bez dodatkowych opcji wysyła GET. Ponieważ adres zaczyna się od /, używa tego samego serwera i portu co strona. W tym ćwiczeniu nie potrzebujemy konfiguracji CORS.

await fetch(...) czeka na odpowiedź, a await response.json() odczytuje jej treść i zamienia JSON na obiekt JavaScript. Funkcja obsługująca formularz ma dlatego słowo async.

Status 400 nie powoduje automatycznie wyjątku w fetch(). Sprawdzamy response.ok, które jest prawdziwe dla statusów od 200 do 299. Nasze API przy błędzie zwraca JSON z polem error, więc możemy wyświetlić komunikat.

catch obsługuje między innymi brak połączenia i błąd odczytania JSON. finally ponownie włącza przycisk niezależnie od wyniku, także po wcześniejszym return.

5. Wyświetl wynik jako tekst

Wstawiamy odpowiedź przez textContent. Przeglądarka traktuje ją jako tekst, a nie kod HTML. Nie używaj tutaj innerHTML: do prezentacji sumy i komunikatów nie potrzebujemy interpretowania znaczników.

Przycisk jest wyłączony podczas oczekiwania, a obszar role="status" pozwala technologiom wspomagającym poinformować o aktualizacji wyniku.

6. Zobacz żądanie w narzędziach przeglądarki

Otwórz narzędzia deweloperskie i zakładkę Network / Sieć. Wyślij formularz i wybierz żądanie add.

Sprawdź:

  1. Metodę GET i pełny adres żądania.
  2. Parametry a i b.
  3. Status odpowiedzi.
  4. Typ treści application/json.
  5. Pola odpowiedzi w zakładce Response / Odpowiedź.

Przy odświeżeniu strony zobaczysz też osobne żądania dokumentu HTML, CSS i JavaScriptu. Serwer nie wysyła całej aplikacji jednym plikiem.

7. Przetestuj błędy świadomie

Błędne dane sprawdzaj przez bezpośredni adres API: przeglądarka może nie dopuścić tekstu hello w polu liczbowym. To pokazuje, dlaczego serwer musi sam walidować dane.

Opcjonalnie sprawdź brak połączenia: pozostaw stronę otwartą, zatrzymaj Flask przez Ctrl+C (albo docker stop flask-calculator-lab w wariancie Docker) i ponownie wyślij formularz. Powinien pojawić się komunikat o nieudanym pobraniu odpowiedzi. Uruchom serwer ponownie przed dalszą pracą.

Sekcja 6. Dockerfile: aplikacja bez lokalnego Pythona

Uruchomisz ten sam kalkulator w kontenerze. Na komputerze potrzebujesz edytora, przeglądarki oraz działającego Dockera. Python i Flask będą zainstalowane wewnątrz obrazu. Kod app.py, szablon HTML, CSS i JavaScript pozostają takie jak w poprzednich sekcjach.

1. Sprawdź Docker

Uruchom Docker Desktop, jeśli używasz go na swoim komputerze, i poczekaj na gotowość silnika. W terminalu wykonaj:

docker version
docker compose version

Pierwsze polecenie powinno pokazać informacje o kliencie i serwerze. Sam numer wersji klienta nie potwierdza działającego silnika. Jeśli pojawia się błąd połączenia, uruchom Docker lub zgłoś problem prowadzącemu. Nie rozwiązuj go przez przypadkowe użycie sudo.

Pierwsze budowanie obrazu wymaga internetu do pobrania obrazu Pythona i pakietów. Przygotuj środowisko przed wykonywaniem zadania.

2. Dodaj pliki konteneryzacji

W katalogu flask-calculator, obok app.py, utwórz requirements.txt, Dockerfile i .dockerignore. Za chwilę dodasz również docker-compose.yml:

flask-calculator/
├── app.py

├── Dockerfile

├── docker-compose.yml     # Added in section 7
├── templates/
│   └── index.html

    ├── style.css

Jeśli wcześniej utworzyłeś .venv, może pozostać na komputerze. Nie będzie wykorzystywane do uruchomienia aplikacji w kontenerze.

Do requirements.txt wpisz:

Flask==3.1.3

To wersja Flask przyjęta w tym ćwiczeniu. Zależności zostaną zainstalowane poleceniem z Dockerfile, bez uruchamiania lokalnego pip. Plik przypina bezpośrednią zależność; nie jest pełnym plikiem blokady wszystkich zależności pośrednich.

3. Napisz kompletny Dockerfile

Plik ma nazywać się dokładnie Dockerfile, bez rozszerzenia .txt. Wpisz:

FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt ./
RUN python -m pip install --no-cache-dir -r requirements.txt

COPY app.py ./
COPY templates/ ./templates/
COPY static/ ./static/

EXPOSE 5000

CMD ["python", "-m", "flask", "--app", "app", "run", "--host=0.0.0.0", "--port=5000"]
Instrukcja Działanie
FROM python:3.12-slim Wybiera bazowy obraz z Pythonem 3.12 i ograniczonym zestawem narzędzi systemowych.
WORKDIR /app Ustawia katalog roboczy wewnątrz obrazu.
COPY requirements.txt ./ Kopiuje listę zależności do katalogu roboczego.
RUN ... pip install ... Instaluje Flask podczas budowania obrazu.
Kolejne COPY Umieszczają kod i zasoby w obrazie.
EXPOSE 5000 Dokumentuje port używany przez aplikację.
CMD [...] Określa polecenie uruchamiane przy starcie kontenera.

Instrukcja RUN wykonuje się przy budowie, a CMD przy uruchomieniu kontenera. Najpierw kopiujemy zależności, później kod: Docker może wykorzystać warstwę z instalacją pakietów, jeśli zmienił się kod, ale nie lista zależności.

Nie aktywujemy .venv i nie kopiujemy środowiska z komputera. Obraz ma własnego Pythona i własne pakiety.

4. Rozróżnij adres nasłuchiwania i port

W kontenerze Flask nasłuchuje na 0.0.0.0:5000, czyli na wszystkich jego interfejsach IPv4. Nasłuchiwanie wyłącznie na 127.0.0.1 wewnątrz kontenera nie wystarcza do obsługi połączeń przekazanych z komputera.

W przeglądarce nadal wpiszesz http://localhost:5000, a nie http://0.0.0.0:5000. Port komputera połączymy z portem kontenera w poleceniu docker run. Samo EXPOSE nie wykonuje tego mapowania.

Używamy lokalnego serwera laboratoryjnego bez trybu debugowania. Konfiguracja serwera produkcyjnego nie jest częścią tego ćwiczenia.

5. Przygotuj .dockerignore

Do .dockerignore wpisz:

.venv/
.git/
__pycache__/
*.pyc
.env
.DS_Store

Plik ogranicza zawartość kontekstu przekazywanego do budowania. Dzięki temu lokalne środowisko i historia Git nie są przesyłane jako część kontekstu. Nasz Dockerfile dodatkowo kopiuje jawnie tylko wymagane pliki aplikacji.

.dockerignore nie zastępuje .gitignore: te pliki służą różnym narzędziom.

6. Zbuduj obraz

Otwórz terminal w katalogu zawierającym Dockerfile i wykonaj:

docker build -t flask-calculator:lab .

-t nadaje obrazowi nazwę i tag. Końcowa kropka wskazuje bieżący katalog jako kontekst budowania. Ścieżki źródłowe w COPY odnoszą się do tego kontekstu.

Adres 127.0.0.1 w mapowaniu ogranicza dostęp do komputera, na którym pracujesz. To inny kontekst niż 0.0.0.0 w poleceniu Flaska: pierwszy określa publikację portu na komputerze, drugi nasłuchiwanie procesu wewnątrz kontenera.

Terminal będzie pokazywał logi. Otwórz:

Dopiero po dodaniu fetch() formularz pokaże sumę bez przeładowania dokumentu. Aplikacja działa również wtedy, gdy na komputerze nie ma polecenia python.

8. Sprawdź proces i zatrzymaj aplikację

W ścieżce podstawowej najpierw wykonaj sekcję 5 z działającym kontenerem. Poniższe polecenia diagnostyczne możesz wykonać po sprawdzeniu fetch; zatrzymanie aplikacji jest potrzebne przed przejściem do Compose.

Zatrzymaj kontener, ponownie wykonaj docker build, a następnie docker run z poprzednich kroków. Odśwież stronę i sprawdź zmianę.

Sekcja 7. Ta sama aplikacja przez Docker Compose

Compose zapisuje sposób budowania i uruchomienia w pliku YAML. Nadal używa tego samego Dockerfile, kodu i obrazu Pythona. Dla tego ćwiczenia definiujemy jedną usługę web.

1. Utwórz docker-compose.yml

W katalogu obok Dockerfile wpisz kompletną konfigurację:

services:
  web:
    build: .
    image: flask-calculator:lab
    ports:
      - "127.0.0.1:5000:5000"

W YAML stosuj spacje, nie tabulatory, i zachowaj wcięcia. Korzystamy z polecenia docker compose, z odstępem. Nie dodajemy starego pola version.

2. Porównaj z wcześniejszymi poleceniami

Konfiguracja Compose Odpowiednik
build: . Kontekst użyty przez docker build ... ..
image: flask-calculator:lab Nazwa i tag budowanego obrazu.
ports Mapowanie z docker run -p ....
Polecenie startowe Nadal pochodzi z CMD w Dockerfile.

Nie przepisujemy instalacji pakietów do YAML. Compose opisuje usługę, a Dockerfile budowę jej obrazu.

Nie ustawiamy container_name: Compose sam nada nazwę związaną z projektem i usługą. W poleceniach Compose będziemy używać nazwy usługi web.

3. Sprawdź i uruchom konfigurację

Najpierw zatrzymaj kontener uruchomiony przez docker run, aby zwolnić port. W katalogu z docker-compose.yml wykonaj:

docker compose config
docker compose up --build

config odczytuje i sprawdza konfigurację. up --build buduje obraz według Dockerfile i uruchamia usługę. Sprawdź ponownie stronę, formularz i bezpośredni adres API.

Ctrl+C zatrzymuje usługę uruchomioną na pierwszym planie. Aby usunąć jej kontener i utworzoną sieć, wykonaj:

docker compose down

4. Uruchom w tle i odczytaj logi

docker compose up --build -d
docker compose ps
docker compose logs web

-d pozwala wrócić do terminala, gdy kontener działa w tle. Aby obserwować logi na bieżąco:

docker compose logs -f web

Ctrl+C kończy obserwację logów, ale nie zatrzymuje usługi działającej w tle. Zatrzymasz ją przez docker compose down.

Sprawdź interpreter w usłudze:

docker compose exec web python --version

5. Zmień kod lub port

Po zmianie HTML, CSS, JavaScriptu lub Pythona wykonaj:

docker compose up --build -d

Compose przebuduje obraz i w razie potrzeby odtworzy kontener. Sam docker compose restart nie kopiuje zmienionych plików do obrazu. Na tym etapie nie dodajemy montowania katalogów ani automatycznej synchronizacji.

Aby użyć portu 5001 na komputerze, zmień tylko wpis ports:

ports:
  - "127.0.0.1:5001:5000"

Zachowaj jego położenie wewnątrz usługi web i uruchom ponownie docker compose up --build -d. Korzystaj z http://localhost:5001.

Sekcja 8. Git i wysłanie projektu na GitHub

Zapiszesz historię kalkulatora w Git i wyślesz kod na GitHub. Pracuj w katalogu flask-calculator, zawierającym app.py i Dockerfile. Nie wykonuj tych poleceń w repozytorium materiałów kursu ani w katalogu nadrzędnym obejmującym wszystkie projekty.

Git przechowuje historię lokalnie. GitHub udostępnia zdalne repozytorium, do którego wysyłamy commity. Sam push nie uruchamia aplikacji: do działania Flaska nadal potrzebny jest serwer lub kontener. GitHub Pages obsługuje strony statyczne i nie wykonuje naszego backendu Pythona.

1. Sprawdź Git i katalog roboczy

W terminalu otwartym w flask-calculator wykonaj:

git --version
git status

Jeśli projekt nie ma jeszcze repozytorium, drugie polecenie zwróci komunikat not a git repository. To oczekiwany stan przed inicjalizacją.

Jeśli git status pokazuje pliki spoza kalkulatora, zatrzymaj się i sprawdź katalog: możesz znajdować się wewnątrz innego repozytorium. Nie twórz zagnieżdżonego repozytorium bez uzgodnienia z prowadzącym.

2. Przygotuj .gitignore

Obok app.py utwórz .gitignore i wpisz:

.venv/
__pycache__/
*.pyc
.env
.DS_Store

Nie wysyłamy środowiska wirtualnego ani plików tymczasowych. Kod, szablon, zasoby, requirements.txt, Dockerfile, .dockerignore i docker-compose.yml powinny trafić do repozytorium.

.gitignore dotyczy Gita, a .dockerignore kontekstu budowania Dockera. Potrzebujemy obu. Reguła ignorowania nie usuwa z historii pliku, który został już zapisany w commicie.

3. Dodaj instrukcję uruchomienia

Utwórz README.md z poniższą treścią. Dokumentację projektu zapisujemy po angielsku:

# Flask Calculator

A small Flask application with an HTML form and a JSON addition API.

## Requirements

- Docker Engine or Docker Desktop
- Docker Compose

Local Python installation is not required for the Docker workflow.

## Run

```bash
docker compose up --build -d
```

Open http://localhost:5000/ in a browser.

## API example

GET http://localhost:5000/api/add?a=2&b=3

A successful response contains `a`, `b`, `operation`, and `result`.
Invalid or missing numbers produce a JSON error with HTTP status 400.

## Logs and shutdown

```bash
docker compose logs web
docker compose down
```

Jeżeli zmieniłeś port w Compose, popraw również adresy w README. Instrukcja powinna odpowiadać rzeczywistej konfiguracji projektu.

4. Zainicjalizuj repozytorium

Dla nowego projektu wykonaj:

git init -b main

Polecenie tworzy lokalne repozytorium i gałąź main. Jeżeli w tym projekcie masz już repozytorium, pomiń inicjalizację i sprawdź nazwę bieżącej gałęzi przez git branch --show-current.

Dla dalszych kroków przyjmujemy gałąź main. Jeśli istniejące repozytorium używa innej nazwy, uzgodnij ją z prowadzącym przed dodaniem zdalnego repozytorium. Jeśli Git jest starszy i nie rozpoznaje -b, dla nowego repozytorium użyj:

git init
git branch -M main

5. Ustaw autora commitów

Sprawdź bieżące ustawienia:

git config user.name
git config user.email

Jeśli są puste lub nieprawidłowe, ustaw dane lokalnie dla tego repozytorium:

git config --local user.name "Jan Kowalski"
git config --local user.email "YOUR_COMMIT_EMAIL"

Zastąp przykładowe nazwisko i YOUR_COMMIT_EMAIL własnymi wartościami. Możesz użyć adresu noreply wskazanego w ustawieniach adresów e-mail konta GitHub. Dane autora trafiają do commitów; nie są hasłem ani konfiguracją logowania.

6. Wybierz pliki do pierwszego commita

Najpierw sprawdź stan:

git status --short

Dodaj konkretne pliki:

git add app.py requirements.txt templates/index.html static/style.css static/app.js Dockerfile docker-compose.yml .dockerignore .gitignore README.md

git add zapisuje wybraną zawartość w indeksie, czyli zestawie zmian przygotowanych do commita. Nie wysyła nic na GitHub.

Sprawdź przygotowany zestaw:

git diff --cached --stat
git diff --cached
git status

Upewnij się, że nie dodano .venv, haseł ani plików niezwiązanych z projektem. Jeśli plik edytowano po git add, dodaj go ponownie, aby commit zawierał aktualną wersję.

7. Zapisz pierwszy commit

git commit -m "Add Flask calculator with JSON API and Docker setup"
git log --oneline -3
git status

Commit jest lokalnym punktem historii. Komunikat opisuje zmianę po angielsku w trybie rozkazującym. Po zapisaniu wszystkich zmian git status powinien pokazać czysty katalog roboczy.

Rozróżniaj trzy kroki: add wybiera zawartość, commit zapisuje ją w lokalnej historii, push wysyła commity do repozytorium zdalnego.

8. Utwórz puste repozytorium na GitHubie

Zaloguj się do własnego konta GitHub i wybierz utworzenie nowego repozytorium:

  1. Nadaj nazwę flask-calculator.
  2. Wybierz widoczność zgodną z ustaleniami prowadzącego. Przy repozytorium prywatnym zapewnij prowadzącemu dostęp do odbioru pracy.
  3. Nie dodawaj automatycznie README, .gitignore ani licencji — zaczynamy od pustego repozytorium, ponieważ pliki i commit masz już lokalnie.
  4. Utwórz repozytorium i skopiuj jego adres HTTPS z sekcji konfiguracji lub przycisku Code.

Przykładowy adres ma postać:

https://github.com/YOUR_USERNAME/flask-calculator.git

YOUR_USERNAME jest miejscem do zastąpienia, nie tekstem, który Git uzupełni automatycznie. Najlepiej skopiuj pełny adres swojego repozytorium z GitHuba.

9. Połącz lokalne repozytorium ze zdalnym

W katalogu projektu wykonaj polecenie z własnym adresem:

git remote add origin https://github.com/YOUR_USERNAME/flask-calculator.git
git remote -v

origin to umowna nazwa zdalnego repozytorium. Polecenie dodaje adres, ale nie tworzy repozytorium na GitHubie i nie wysyła jeszcze plików.

Jeżeli origin już istnieje, najpierw sprawdź jego adres przez git remote -v. Nie usuwaj go w ciemno. Jeśli jest błędny, skonsultuj zmianę z prowadzącym.

10. Wykonaj pierwszy push

git push -u origin main

main wskazuje wysyłaną gałąź. -u zapisuje powiązanie ze zdalną gałęzią, dzięki czemu kolejne wysłanie zwykle wymaga tylko git push.

Przy HTTPS Git może uruchomić logowanie przez przeglądarkę lub menedżera poświadczeń. Hasło do konta GitHub nie służy do uwierzytelniania operacji Git przez HTTPS. Jeśli konfiguracja wymaga tokenu dostępu, użyj go zgodnie z instrukcją prowadzącego; nie wpisuj tokenu do adresu repozytorium ani do plików projektu. Jeżeli masz już skonfigurowane SSH, możesz użyć adresu SSH skopiowanego z własnego repozytorium.

Po sukcesie odśwież repozytorium w przeglądarce. Sprawdź pliki, wyświetlony README i komunikat commita. Git wysyła zawartość commitów, a nie wszystkie pliki widoczne na dysku.

11. Zapisz i wyślij kolejną zmianę

Zmień opis autora w templates/index.html. Następnie:

git diff
git add templates/index.html
git diff --cached
git commit -m "Update calculator author description"
git push

Zobacz na GitHubie nowy commit i jego diff. W kolejnych zmianach stosuj ten sam cykl: edycja, kontrola, dodanie wybranych plików, commit i push.

Zmiana w repozytorium nie aktualizuje automatycznie wcześniej zbudowanego kontenera. Aby zobaczyć ją lokalnie, wykonaj ponownie docker compose up --build -d i odśwież stronę.

12. Po zajęciach: sprawdź projekt po pobraniu

Możesz sprawdzić kompletność repozytorium w osobnym katalogu, bez korzystania z lokalnej .venv. Użyj własnego adresu i nowej nazwy katalogu:

git clone https://github.com/YOUR_USERNAME/flask-calculator.git flask-calculator-check
cd flask-calculator-check
docker compose up --build -d

Przed uruchomieniem zatrzymaj wcześniejszą instancję kalkulatora, aby zwolnić port 5000. Otwórz stronę, oblicz sumę i sprawdź API. Na końcu w sklonowanym katalogu wykonaj:

docker compose down

Ta próba pokazuje, czy repozytorium zawiera wszystkie potrzebne pliki. Sam widok plików na GitHubie nie potwierdza, że inna osoba potrafi uruchomić projekt.

14. Oddanie projektu

Oddaj link do repozytorium, nie adres lokalnej aplikacji localhost. Repozytorium powinno zawierać:

  • kod Flaska, HTML, CSS i JavaScript;
  • requirements.txt, Dockerfile i docker-compose.yml;
  • .gitignore, .dockerignore oraz działającą instrukcję w README;
  • co najmniej dwa commity pokazujące pierwszą wersję i późniejszą zmianę.

Końcowy punkt kontrolny: prowadzący ma dostęp do repozytorium, a po jego sklonowaniu można uruchomić kalkulator przez docker compose up --build, otworzyć formularz i uzyskać JSON z sumą dwóch liczb.
